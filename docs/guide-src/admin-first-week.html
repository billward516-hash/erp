This page is the short route from a freshly installed system to a company that is ready to use. It is written for the person who will administer the system: you do not need to be a developer, but you should be comfortable with spreadsheets, your company's sign-in service, and working with whoever hosts the server. Each day lists what to do and where to read more. Smaller companies can fold several days into one.

Everything under the Admin menu heading needs the administrator role (the tenant.admin permission). The first administrator is created when the company is set up on the server (see First deployment); that person does the steps below.

Before day one: the server

Whoever runs the server does this once. It is not an Administrator-screen task, but nothing else works until it is done.

  • The server is installed with its two database logins, a persistent folder for uploaded files, and a secure (https) address. /ready answers OK.
  • The company and its first administrator exist, and you have been given a sign-in token for that administrator (a long code beginning erp_).
  • Someone has decided who will send email (see Scheduled jobs: the digest email is not delivered until a mail service is connected) and where backups go.

Details are in Security and operations.

Day 1: sign in, then describe the company

  1. Open the address. On the Sign in page, open the fold-out Development sign-in with an API token, paste the administrator token and choose Sign in with token. (Single sign-on comes on day 3.)
  2. Open Admin → Fit interview and answer the questions about what the business does. Choose Save answers and show the recommendation. You get a suggested set of features, a suggested plan depth and a list of things that are not a fit yet. Read the fit interview before pressing the optional Hide the features we did not recommend button; you can leave it for day 4.
  3. Open Admin → Implementation. Pick a depth (Guided, Standard or Full), optionally a target go-live date, and choose Build the plan. The plan is your checklist from here on. See Implementation planner.
  4. Open Admin → Sites and add every plant, store, warehouse, office or property. Give each its right time zone. See Sites. Many sites at once: use the Sites (properties, stores, plants) import.

Day 2: people and roles

  1. Open Admin → Data import and load Employees / technicians from your payroll or HR export (no pay data needed). See Importing data.
  2. Add the people who sign in. One at a time: Admin → People and access, Add a person, then Give role with the site (or All sites). Many at once: load People who sign in, with roles in the import, one row per person and role, with the work email, the employee number, the role and the site (blank means all sites). See People who sign in. If a starter role does not fit, make a company role on the Roles tab (Standard).
  3. Give at least two people the Administrator role. A company rollback needs a second administrator to confirm it (see Archives and recovery), and you do not want one lost login to lock everyone out of administration.
  4. In Admin → Implementation, mark the steps Verify as you check them and give each remaining step an Owner.

Day 3: single sign-on

  1. Ask whoever runs your identity provider (Microsoft Entra ID, Google Workspace, Okta and similar) to register the platform as a web application, using the redirect address shown on Admin → Sign-in.
  2. Enter the issuer, client id, client secret and your work-email domains. Tick Single sign-on is on and save.
  3. Sign out, and sign back in with your work email. Ask a second person to try.
  4. Once two people have signed in this way, revoke the first administrator token under Admin → People and access → Tokens (it expires by itself after 14 days), and decide whether to switch off API tokens. Issue any tokens your scripts need there, each with an expiry.

All the details, including what to give the provider, are in Sign-in.

Day 4: tailor what people see and what reminds them

  1. Admin → Features: hide the areas the company does not use, or show some of them to only some roles. See Features and editions.
  2. Admin → Reminders: look through the 33 reminders the system sends, turn off the ones you do not want and adjust lead times. See Reminders and retention.
  3. Admin → Data retention: confirm how long short-lived working data is kept. The defaults are sensible for most companies.
  4. If the company uses the built-in books, set them up in Books; if it uses outside accounting software, open Admin → Accounting. See Accounting connection.

Day 5: rehearse, protect, and check the machinery

  1. In the Rehearse and go live section of the plan, make a practice copy and run your real files through it before loading the real company. See Practice copy.
  2. Load the rest of the data steps in the order the plan gives. Each import has a check step that saves nothing; fix the problems file and try again. See Importing data.
  3. Open Admin → Archives and restore and choose Archive now, so you have a clean starting point. Ask the server operator to confirm that database backups are running and that a restore has been tried (backup drill).
  4. Open Admin → Scheduled jobs and choose Run it now for this company once to see that every step reports done. See Scheduled jobs.
  5. Complete Final changes and cutover and Go-live sign-off in the plan.

After go-live: the routine

How oftenWhat
Every day (automatic)The daily job runs: reminders, email digests, retention, archives and document reviews. Glance at Scheduled jobs now and then.
WeeklyCheck that Scheduled jobs shows a recent day; look at Admin → Accounting for items that Need attention if you use a connection.
QuarterlyReview who has the Administrator role and who has left (People and access: disable leavers, check Last used on tokens and revoke any that are not needed); ask the server operator to run the backup drill; review the Features and Reminders settings.
When something changesNew site: add it and grant roles. New starter: add a row to the people import. A mistake in a bulk load: see Archives and recovery.
