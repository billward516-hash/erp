    Administrator brief

    Importing data

    Bring existing spreadsheets and exports into the system safely: choose a target, match columns, check every row, import, and undo a mistake.

    Administrator brief: more technical, written for the person who sets the system up.

    On this page
    • Run an import
    • Reading the check
    • What can be imported, and in what order
    • Undoing a mistake
    • Practice first
    • Messages you may see

    The import wizard loads data from the files a company already has (CSV, Excel or JSON) without custom programming. It matches your columns to the system's fields, checks every row before anything is saved, tells you exactly what is wrong with the rows that fail, and can remember the mapping for next time. Importing the same file again updates records instead of duplicating them.

    Anyone with the imports.run permission can open Admin → Data import and check a file. Saving the rows needs imports.commit and, for most targets, the permission of the area being loaded (for example books.manage for bank lines, purchasing.manage for suppliers, tenant.admin for sites and people). Finance, buyers, sales and production roles hold the right pairs for their own data; see the Permissions table.

    Run an import

    1. Open Admin → Data import. The page is called Bring in existing data and shows four stages: Choose file, Match columns, Check, Imported.
    2. Under What are you importing? pick a target (the table below). A short description appears. No file yet? Choose Excel template or CSV template: you get a file with the column names the importer recognises, an example row and an explanation of every column.
    3. In Where does the file come from? type a short name for the source system, such as old-cmms or payroll. Use the same name every time you load from that system; it is how a later load finds the same records.
    4. If every row belongs to one site, choose it under Default facility; otherwise leave it and let the rows name their sites.
    5. Choose the file (.csv, .tsv, .xlsx or .json; an old .xls must be saved as .xlsx or CSV first). Uploads are limited to about 50 MB by default. Choose Match columns.
    6. On Match columns, each system field shows the column the importer chose, with a confidence label (high, medium, low, or manual if you changed it) and an example value. Correct any wrong choice from the drop-down; — not imported — skips a field. A red note lists required fields still unmatched.
    7. For fields with a fixed list of values (such as priority), the page asks you to Translate any value it could not recognise, for example “Hot” to a priority.
    8. Under Options choose whether unmatched columns are kept as extra fields on the record or ignored (ignore them for anything private such as tax numbers), and whether 03/04/2025 means March 4 or 3 April. This only breaks ties; a column containing 25/04/2026 is read day-first automatically.
    9. Use Leave out rows where… to skip inactive items, test rows or other sites' data (for example Status is Inactive).
    10. Choose Check every row (nothing is saved yet).
    11. Read the results (next section). When you are satisfied, choose Import N rows.
    12. On the final page, name and save the mapping with Save mapping. Next time, pick it under Saved mapping and choose Check with saved mapping.

    Reading the check

    ItemMeaning
    Rows readData rows found, after the header and blank lines.
    New records / UpdatesWhat would be created and what would be changed because the record already exists. A blank cell never erases an existing value.
    With warningsRows that will import, but with an assumption you should know about (for example an ambiguous date order or an unknown unit that is kept as typed).
    With errorsRows that cannot be imported, each with its reason.
    Things these rows name that are not loaded yetFor example “12 rows name 3 suppliers that are not loaded”. Load those first or fix the spelling.
    PreviewThe first rows as they will be saved, with create, update or skip.

    If there are errors, choose Download problems file. It contains the failing rows with their original values and a reason for each (and, for wide sheets, the exact column), so the owner of the data can fix their spreadsheet and you can check again. By default any error blocks the whole import. Ticking Import the good rows and skip the N with errors loads the good rows only and reports the rest.

    Nothing touches live records until you choose Import. You can run the check as often as you like. Checking and importing are separate steps: the import checks the rows again against current data when you press the button, so rows that became invalid in between are reported then.

    The complete list, every field and the header spellings it recognises are shown on the matching screen. The Excel template for each target is the quickest guide.

    Things that surprise people

    • Stock on hand sets, it does not add. Each row sets the on-hand quantity; the difference to the current balance is posted as an opening movement. Loading the same file twice changes nothing.
    • Bills of material and routings land on a draft revision. Nothing reaches production until a person releases it.
    • Customer forecasts land as drafts and must be activated after review.
    • Opening balances refuse receivables, payables and employee reimbursement accounts: those come from open invoices and bills.
    • Open invoices and bills are loaded as a single “balance brought forward” line and are not sent to accounting.
    • History (work orders, nonconformances, incidents, calibrations) arrives as records only; no workflow runs and nothing is raised for past events.
    • Timestamps with no time zone are read in the time zone of the row's site, including daylight-saving changes.
    • Not imported by design: approval rules, reminder settings, feature visibility, retention, courses with assessments, FMEA, continuity plans, change records, CAPA workflows, audits, policies and announcements. They are decisions made in the product.
    • Do not import pay rates, bank details or tax numbers. Choose Ignore for unmatched columns when the export carries them.

    Undoing a mistake

    The wizard has no “undo this import” button. Plan for it:

    1. Before a large or risky load, open Admin → Archives and restore and choose Archive now. This takes a full copy of the company's data (on a two-year, 20,000-ledger-line test company it took about five seconds).
    2. If an import overwrote or removed records, open the archive, choose Bring records back, select the kind of record, tick those shown as changed or deleted and choose Bring back.
    3. If the whole load was wrong, roll the company back to the archive (a second administrator must confirm). Everything entered since is replaced, so only do this soon after the import. See Archives and recovery.

    Re-importing a corrected file is often the simplest fix: it updates the records in place by their numbers.

    Practice first

    Use the practice copy (Implementation planner) to run the first file of each kind and read the problem report with the data's owner. The real company is not touched. The staged rows of a finished import are deleted after the number of days set under Admin → Data retention (default 90); the summary stays. See Reminders and retention.
