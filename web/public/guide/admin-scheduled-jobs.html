    Administrator brief

    Scheduled jobs

    What the daily job does for your company, how to see that it ran, how to run it by hand, and what is not scheduled.

    Administrator brief: more technical, written for the person who sets the system up.

    On this page
    • When it runs
    • What it does for your company
    • The Scheduled jobs page
    • What is not on this schedule
    • If a step fails

    Once a day the server runs a housekeeping job for every company. It sends reminders, builds email digests, clears out expired working data, takes the company archive when one is due, and chases late reviews, expiring quotes and similar items. You do not need to start it, but you should know how to check that it ran, because a silent failure means people stop getting reminders.

    Only an administrator sees Admin → Scheduled jobs.

    When it runs

    • The server checks every minute. Once the configured hour has passed (06:00 UTC by default; the setting is DAILY_JOB_HOUR_UTC) and today's job has not yet been claimed, it runs. It runs once per calendar day (UTC).
    • If the server was down at 06:00, the job runs when it comes back up, as long as the day is not over.
    • If several copies of the server run, the first to claim the day's row does the work and the others do nothing, so nothing is sent twice.
    • The operator may switch the built-in scheduler off (DAILY_JOB_ENABLED=false) and use an outside scheduler instead. The page then says “The built-in daily job is switched off on this server; an external scheduler must run it.”

    What it does for your company

    Each company gets these steps, in order. A failure in one step is recorded and does not stop the next step; a failure in one company does not stop other companies.

    StepWhat happensSettings
    RemindersSends every reminder that is due: maintenance, quality, safety, people, purchasing and finance, stock and sites, and periodic reviews. Each is sent once per its dedupe rule, so a second run the same day does not duplicate.Reminders
    DigestsBuilds one email per person who wants email and has unread notifications not yet emailed (up to 50 items), then hands it to the mail sender. See the note on email below.Each person's notification settings
    RetentionRemoves working data older than the periods you set: finished import rows, read and unread notifications, sent emails, unsaved form entries, expired tokens. It runs after the mail step so nothing is removed before it is sent.Data retention
    ArchivesTakes a company archive if the last is older than the interval (30 days by default), prunes scheduled archives beyond the number kept (12 by default), and expires rollback requests older than 24 hours.Archives
    Documents and othersBrings released document revisions into force on their effective date; reminds about overdue document readings and specification reviews, late supplier RFQs and customer RFQs, quotes about to expire, unacknowledged change notices; sweeps temporary changes that have ended; generates service visits from agreements (only at sites licensed for field service); checks tool calibration for service vehicles.Reminders; Features; licence

    About the email digest

    In the current build the mail step writes each message as a file in the server's storage folder (mail) and marks it as handled; it does not send email. The page and the code call this the development adapter. Until a mail service and sending domain are connected (an open decision for the owner; the plan step Outgoing email tracks it), people receive reminders only in the notification bell on the screen. Do not promise email reminders to users before this is done.

    The Scheduled jobs page

    The sentence at the top is the answer to “is it working?”:

    • “The daily job last ran on 2026-10-22 (done); it runs every day at 06:00 UTC.” Good.
    • “No daily job has run yet; the first runs at 06:00 UTC.” Normal on a new system.
    • “The daily job has not run since …: check the server.” It last ran more than 36 hours ago. Tell the server operator.

    The table shows the last 14 days with Day, Result (Done, Failed or Running), Started by (The schedule or A person), Started and This company. The last column says All steps done or A step failed: <step>: <reason>. A day shown as Failed because of another company does not mean yours failed; read your own column.

    Run it now

    1. Choose Run it now for this company. The button reads Running… while it works.
    2. When it finishes the page reloads. It does not show a result message; look for its effects: new reminders in Notifications, and a new row under Recent sweeps on Data retention. An error, if any, appears in red under the heading.

    Running it now is safe to repeat: reminders are not duplicated for the same day, and the archive step only acts when one is due. Use it after changing reminder settings or retention periods to see the effect straight away, or after the server was down.

    What is not on this schedule

    • The accounting sync. It runs only when someone presses Sync now or the operator schedules it separately. See Accounting connection.
    • Database backups belong to the hosting setup (Security and operations).
    • Anything else you may wish to automate. The product has no general scheduler or job editor.

    If a step fails

    WhereWhat to do
    A step failed: reminders: …Copy the message and give it to the server operator with the date; the other steps still ran.
    A step failed: archives: …Often storage space or permissions on the storage folder. Without archives you lose the undo safety net; fix soon.
    Nothing at all for daysThe server may be down, or the built-in scheduler may be switched off. Check /health and ask the operator.
