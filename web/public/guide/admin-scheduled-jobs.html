    Administrator brief

    Scheduled jobs

    What the daily job does for your company, how to see that it ran, how to run it by hand, and what is not scheduled.

    Administrator brief: more technical, written for the person who sets the system up.

    On this page
    • When it runs
    • What it does for your company
    • The Scheduled jobs page
    • What is not on this schedule
    • If a step fails

    Once a day the server runs a housekeeping job for every company. It sends reminders, builds and sends email digests, syncs the accounting system, clears out expired working data, takes the company archive when one is due, and chases late reviews and similar items. You do not need to start it, but you should know how to check that it ran, because a silent failure means people stop getting reminders.

    Only an administrator sees Admin → Scheduled jobs.

    When it runs

    • The server checks every minute. Once the configured hour has passed (06:00 UTC by default; the setting is DAILY_JOB_HOUR_UTC) and today's job has not yet been claimed, it runs. It runs once per calendar day (UTC).
    • If the server was down at 06:00, the job runs when it comes back up, as long as the day is not over.
    • If several copies of the server run, the first to claim the day's row does the work and the others do nothing, so nothing is sent twice.
    • The operator may switch the built-in scheduler off (DAILY_JOB_ENABLED=false) and use an outside scheduler instead. The page then says “The built-in daily job is switched off on this server; an external scheduler must run it.”

    What it does for your company

    Each company gets these steps, in order. A failure in one step is recorded and does not stop the next step; a failure in one company does not stop other companies.

    StepWhat happensSettings
    RemindersSends every reminder that is due: maintenance, quality, safety, people, purchasing and finance, stock and sites, and periodic reviews. A quote about to expire gets one series of notices (7 days, 2 days, the day after), not two. Each is sent once per its dedupe rule, so a second run the same day does not duplicate.Reminders
    DigestsBuilds one email per person who wants email and has unread notifications not yet emailed (up to 50 items), then hands it to the mail server. A message that cannot be sent is kept and tried again by the next daily run. See the note on email below.Each person's notification settings; the mail server settings of the system
    Accounting syncIf your company has an accounting connection (the built-in books or a provider), sends what is waiting, retries what failed earlier, and brings back payment status. Safe to repeat. If it cannot run, the page shows the reason and each administrator gets one notification a day.Accounting connection
    RetentionRemoves working data older than the periods you set: finished import rows, read and unread notifications, sent emails, unsaved form entries, expired tokens. It runs after the mail step so nothing is removed before it is sent.Data retention
    ArchivesTakes a company archive if the last is older than the interval (30 days by default), prunes scheduled archives beyond the number kept (12 by default), and expires rollback requests older than 24 hours.Archives
    Documents and othersBrings released document revisions into force on their effective date; reminds about overdue document readings and specification reviews, late supplier RFQs and customer RFQs, unacknowledged change notices; sweeps temporary SOP changes (alerts to the owner at 14, 7, 3, 1 and 0 days, then daily once past the end date); generates service visits from agreements (only at sites licensed for field service); checks tool calibration for service vehicles.Reminders; Features; licence

    About the email digest

    Email is delivered only when the server has a mail server set up (SMTP_HOST and the related settings; see Security and operations). When it has not, the mail step writes each message as a file in the server's storage folder (mail); nothing reaches anyone, and the page says so in the Email card. People then receive reminders only in the notification bell.

    What has and has not been proven. The mail sender has been tested only against a stand-in mail server inside the test suite. It has not been run against a real provider or a real sending domain (an open decision for the owner; the plan step Outgoing email tracks it). After a provider is connected, press Send a test email to me and confirm the message arrives and is not filed as spam. Do not promise email reminders to users before you have seen that work.

    If a send fails, the message stays in the queue with the error and is tried again by the next daily run (a message is given up on after five failed attempts or two weeks, and administrators are notified). The job itself carries on with its other steps, and the failure is shown in the This company column. If the mail server cannot be reached at all, messages wait without using up their attempts. A person who turned email off after their digest was queued does not get it.

    The Scheduled jobs page

    The sentence at the top is the answer to “is it working?”:

    • “The daily job last ran on 2026-10-22 (done); it runs every day at 06:00 UTC.” Good.
    • “No daily job has run yet; the first runs at 06:00 UTC.” Normal on a new system.
    • “The daily job has not run since …: check the server.” It last ran more than 36 hours ago. Tell the server operator.

    Under the sentence an Email card says whether the server can send email at all and how many messages are waiting or were given up on. It has the Send a test email to me button: it sends one message to your own address and reports Test email sent or the mail server's error text. The mail password is never shown; if the server echoes it, it is replaced by “[hidden]”. Without a mail server it tells you that nothing was sent.

    The table shows the last 14 days with Day, Result (Done, Failed or Running), Started by (The schedule or A person), Started and This company. The last column lists each step with what it did (for example Reminders: 12 sent, Accounting sync: delivered 3) and shows a step that failed in red with the reason. Runs started by a person show their name. A day shown as Failed because of another company does not mean yours failed; read your own column.

    Run it now

    1. Choose Run it now for this company. The button reads Running… while it works.
    2. When it finishes a result box appears under the heading: green The run finished: every step was done, or red The run finished, but a step failed, with one line per step saying what it did (counts) or why it failed.
    3. The run is also written to the table below as a row marked A person with your name, so you can find it later. It is separate from the scheduled run of the day: running it by hand never stops tonight's run.

    Running it now is safe to repeat: reminders are not duplicated for the same day, the sync does not deliver anything twice, and the archive step only acts when one is due. Use it after changing reminder settings, retention periods or the mail settings to see the effect straight away, or after the server was down.

    What is not on this schedule

    • A faster accounting sync. The sync runs once a day with this job. For fresher figures press Sync now on the integrations page, or ask the operator to schedule scripts/run-sync.ts more often. See Accounting connection.
    • Database backups belong to the hosting setup (Security and operations).
    • Anything else you may wish to automate. The product has no general scheduler or job editor.

    If a step fails

    WhereWhat to do
    A step failed: reminders: …Copy the message and give it to the server operator with the date; the other steps still ran.
    A step failed: archives: …Often storage space or permissions on the storage folder. Without archives you lose the undo safety net; fix soon.
    A step failed: digests: … not deliveredThe mail server refused or could not be reached. The text after the colon is its own error. Messages are kept and retried tomorrow; fix the settings (or ask the operator), then use Send a test email to me.
    A step failed: sync: …The accounting sync could not run (for example nobody who may manage the connection is active). Administrators also get a notification, once a day. See Accounting connection.
    Nothing at all for daysThe server may be down, or the built-in scheduler may be switched off. Check /health and ask the operator.
